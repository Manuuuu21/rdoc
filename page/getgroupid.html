      getgroupid()

      What is getgroupid? 🤔

      The getgroupid() function retrieves the unique numeric ID representing the target character's assigned group or role layout, configured under conf/groups.conf.

      Unlike getgmlevel(), which returns simple permissions integers, getgroupid() corresponds directly to specific role groupings, such as standard players, premium donors, VIP status members, or distinct moderator tiers.

      Syntax of getgroupid? 📜

      • getgroupid({<char_id>})

      Syntax Parameter Explanation 🧩

      Parameter Type Description
      <char_id> (Optional) Integer The character ID of the target player to inspect. If omitted, the check defaults to the active character currently invoking the script.

      Common Group ID Configurations 🧩

      In standard, modern rAthena pre-configured setups, role index groups are mapped in conf/groups.conf as follows:

      Group ID Group Name Description
      0 Player Standard player account class with default command flags.
      1 VIP Player Premium or subscribing character group (allowed custom warpers, etc.).
      10 Support Staff Community helper or customer support moderator roles.
      99 Server Administrator Root administrator group with extensive @ commands access.

      Return Value ↩️

      • Returns an **integer** representing the Group ID. Defaults to 0 if no custom group configuration is matched.

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= VIP-Exclusive Lounge Entrance
//===== By: rAthena AI Assistant ============================
//= Showcases getgroupid() to filter VIP and Staff groups
//============================================================
prontera,150,155,4	script	VIP Lounge Doorman	909,{
    mes "^0000FF[Doorman]^000000";
    mes "Welcome to the Grand Prontera Conservatory!";
    mes "This gate leads straight to the VIP Relaxation Gardens.";
    next;

    // Obtain group ID of active player
    set .@group_id, getgroupid();

    // Check if player is VIP (ID 1) or Staff / Admin (ID >= 10)
    if (.@group_id != 1 && .@group_id < 10) {
        mes "^0000FF[Doorman]^000000";
        mes "I am deeply sorry, but your account group is registered as standard player.";
        mes "Only registered VIP members or Server Staff may enter this pavilion.";
        close;
    }

    mes "^0000FF[Doorman]^000000";
    if (.@group_id == 1) {
        mes "Welcome, VIP Member! Step inside and enjoy your premium refreshments.";
    } else {
        mes "Welcome, Staff Member! Thank you for watching over our adventurers today.";
    }
    next;

    mes "^0000FF[Doorman]^000000";
    mes "Would you like to step inside now?";
    next;

    if (select("Yes, lets go!:No, stay here") == 1) {
        warp "vip_zone", 55, 60;
        end;
    }

    mes "^0000FF[Doorman]^000000";
    mes "Very well. Stay safe out there!";
    close;
}

      In this script:

      The Lounge Doorman NPC exemplifies solid group-based authorization:

      • The command getgroupid() queries the active character's permissions profile on line 12.
      • It cleanly validates whether the account group ID matches VIP credentials (.@group_id == 1) or contains staff privileges (.@group_id >= 10) before executing the teleport mechanism.
