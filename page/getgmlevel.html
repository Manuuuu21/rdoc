      getgmlevel()

      What is getgmlevel? 🤔

      The getgmlevel() function retrieves the Game Master (GM) permissions rank or level associated with the player group of the target character.

      This permits creators to customize script interactions specifically for staff members (e.g. game masters, operators, testing developers), restrict access to configuration menus, protect VIP content, or print diagnostic system readouts only to authenticated administrators.

      Syntax of getgmlevel? 📜

      • getgmlevel({<char_id>})

      Syntax Parameter Explanation 🧩

      Parameter Type Description
      <char_id> (Optional) Integer The character ID of the target player to inspect. If omitted, the function queries the player currently invoking the NPC script.

      Return Values ↩️

      Context / Account State Return Level Interpretation
      Normal Player Account 0 Standard default player level (has no staff or GM authorities).
      GM / Admin Account 1 - 99 Staff member rank value mapping to permissions set in conf/groups.conf.
      Console Input Command 99 Returned automatically when executed directly from a server CLI context.

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= Sandbox Admin & GM Portal NPC
//===== By: rAthena AI Assistant ============================
//= Showcases getgmlevel() to guard access and grant commands
//============================================================
prontera,150,150,4	script	Admin Command Center	909,{
    // Check if player has GM permissions
    if (getgmlevel() == 0) {
        mes "^0000FF[Command Center]^000000";
        mes "I am sorry, adventurer. This machine is protected by system security protocols.";
        mes "Only active Game Masters (GM 1+) may log in here.";
        close;
    }

    mes "^0000FF[Command Center]^000000";
    mes "Access granted! Hello, administrator.";
    mes "Your verified GM Clearance Level is: ^FF0000" + getgmlevel() + "^000000.";
    next;

    mes "^0000FF[Command Center]^000000";
    mes "What system diagnostics or actions would you like to run?";
    next;

    switch (select("Spawn Testing Item:Warp to Staff Lounge:Exit Portal")) {
        case 1:
            // Admin Spawn action
            getitem 501, 100; // Red Potion x 100
            mes "^0000FF[Command Center]^000000";
            mes "Testing materials spawned directly in your inventory.";
            close;

        case 2:
            mes "^0000FF[Command Center]^000000";
            mes "Teleporting you to the developer staff lounge...";
            close;
            warp "sec_in02", 100, 100;
            end;

        case 3:
            mes "^0000FF[Command Center]^000000";
            mes "Portal closed. Have a productive shift!";
            close;
    }
}

      In this script:

      This control console illustrates optimal GM access restriction handling:

      • The function getgmlevel() serves as a highly robust gatekeeper check on line 7 right at script invocation.
      • Because regular players return 0, they are safely filtered out, preventing malicious exploit attempts.
      • GM staff accounts are verified instantly, and can select admin-specific debugging resources comfortably.
