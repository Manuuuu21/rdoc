      getunitdata, setunitdata

      What are getunitdata, setunitdata? 🤔

      This is used to get and set special data related to the unit. With getunitdata, the array given will be filled with the current data. In setunitdata the indexes in the array would be used to set that data on the unit.

      Both getunitdata and setunitdata will return -1 if the given GID does not exist.

      Note: Note: When adjusting a unit's stat (STR, AGI, etc) the unit's respective statuses are recalculated (HIT, FLEE, etc) automatically. Keep in mind that some stats don't affect a unit's status and will have to directly be modified.

      Note: *Notes: - *_SIZE: small (0); medium (1); large (2) - *_MAPID: this refers to the map_data index (from src/map/map.cpp), not the mapindex_db index (from src/common/mapindex.cpp) -- For setunitdata, map name can also be passed in as a valid value instead of map ID - *_SPEED: 20 - 1000 - *_MODE: see doc/mob_db_mode_list.txt - *_LOOKDIR: north (0), northwest (1), west (2), etc - *_CANMOVETICK: seconds * 1000 the unit will be unable to move - *_DMGIMMUNE: unit will be immune to damage (1), or will receive damage (0) - *_HUNGER: 0 - 100 - *_INTIMACY: 0 - 1000 - *_LIFETIME: seconds * 1000 the unit will be alive for - *_AMOTION: see doc/mob_db.txt - *_ADELAY: see doc/mob_db.txt - *_DMOTION: see doc/mob_db.txt - *_BODY2: enable (1) the alternate display, or disable (0) - *_TARGETID: when set to 0 the unit will release the target and stop attacking

      Syntax of getunitdata, setunitdata 📜

      • getunitdata <GID>,<arrayname>;
      • setunitdata <GID>,<parameter>,<new value>;

      Syntax Parameter Explanation 🧩

      Parameter Type Description
      <GID> Integer The unique Game ID (GID) of the target unit (monster, NPC, pet, homunculus, mercenary, or player).
      <arrayname> Array The script array variable to store retrieved data.
      <parameter> Integer Specifies the <parameter> parameter for getunitdata.
      <new value> Integer / String The new value to set for the specified parameter.

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= getunitdata, setunitdata Demonstration NPC
//= Demonstrates how to use getunitdata, setunitdata
//============================================================
prontera,150,150,4	script	GetunitdataDemo	100,{
    mes "[GetunitdataDemo]";
    // Spawn some Porings and save the Game ID.
        // - Keep in mind, when the 'monster' script command is used,
        // - all the spawned monster GID's are stored in an array
        // - called $@mobid[].
        monster "prontera",149,190,"Poring",1002,10;
        .GID = $@mobid[9]; // Store and modify the 10th Poring spawned to make him stronger!

        // Save the strong Poring's mob data in the .@por_arr[] variable. (.@por_arr[1] being level, .@por_arr[13] being class, etc.)
        // With this data we can have the NPC display or manipulate it how we want. This does not have to be ran before 'setunitdata'.
        getunitdata .GID,.@por_arr;

        // Set the max HP of the Poring to 1000 (current HP will also get updated to 1000).
        setunitdata .GID,UMOB_MAXHP,1000;
    close;
}

      In this script:

      • The script defines an NPC object on prontera (or the target map) that triggers when a player interacts with it.
      • It invokes getunitdata with the required arguments as specified in the rAthena scripting reference.
      • Any resulting state change, return value, or player/unit update is processed immediately within the active script execution context.
