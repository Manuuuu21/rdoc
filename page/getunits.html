      getunits, getmapunits, getareaunits

      What are the get*units commands? 🤔

      The getunits(), getmapunits(), and getareaunits() suite of functions allows script creators to count active entities of specific types within distinct scopes.

      Even more powerfully, these functions can automatically populate a target script array with the GIDs (Integer Game IDs) or Names (Strings) of all matched units, permitting high-fidelity scripting iteration over current players, NPCs, or spawned monsters!

      Syntax of getunits and family? 📜

      • getunits(<type>{, <array_variable>[<first value>]})
      • getmapunits(<type>, "<map name>"{, <array_variable>[<first value>]})
      • getareaunits(<type>, "<map name>", <x1>, <y1>, <x2>, <y2>{, <array_variable>[<first value>]})

      Syntax Parameter Explanation 🧩

      Parameter Type Description
      <type> Constant The entity family class constant to query. Standard constants are listed in the table below.
      "<map name>" String The layout key of the target map (e.g. "prontera").
      <x1>, <y1>, <x2>, <y2> Integer Coordinates outlining target rectangular query boundaries.
      <array_variable>[<first value>] (Optional) Array Variable A target variable array reference mapping to list matches.
      • Passing a **String Array** (e.g. .@names$[0]) fills the array with **Display Names**.
      • Passing an **Integer Array** (e.g. .@gids[0]) fills the array with internal **GIDs (Game IDs)**.

      Target Type Constants (<type>) 🎯

      Constant Entity Mapped
      BL_PC Player Character objects
      BL_MOB Monster / Mob structures
      BL_PET Active player Pet structures
      BL_HOM Active homunculus characters
      BL_MER Active mercenary characters
      BL_NPC Active NPC configurations
      BL_ELEM Summoned Elemental units

      Return Values ↩️

      • Returns an **integer** detailing the overall headcount of matching objects successfully scanned.

      Example 1: Using getunits for Player Rosters 💡

      Global Player Broadcaster:
      //===== rAthena Script =======================================
//= Roster Reader NPC
//============================================================
prontera,164,185,4	script	Imperial Scanner	909,{
    mes "^0000FF[Imperial Scanner]^000000";
    mes "Scanning server data...";
    next;

    // Grab the players count and build a string array of the names
    set .@num, getunits(BL_PC, .@names$[0]);

    mes "^0000FF[Imperial Scanner]^000000";
    mes "The total number of Players connected globally is: ^00FF00" + .@num + "^000000.";
    mes "Roster detail list:";
    next;

    // Enable freeloop if arrays might become extremely large (prevents CPU lock errors)
    freeloop(1);
    for (set .@i, 0; .@i < getarraysize(.@names$); set .@i, .@i + 1) {
        mes "Player " + (.@i + 1) + ": ^0055FF" + .@names$[.@i] + "^000000";
    }
    freeloop(0);
    close;
}

      Example 2: Using getmapunits to Count Local NPCs 💡

      Prontera NPC Auditor:
      //===== rAthena Script =======================================
//= NPC Directory Auditor
//============================================================
prontera,160,185,4	script	In-Town Inspector	909,{
    mes "^0000FF[In-Town Inspector]^000000";
    mes "Would you like me to audit all active NPCs loaded within Prontera?";
    next;

    if (select("Yes, run audit:No thanks") == 2) {
        close;
    }

    // Get the local NPC count in Prontera and construct names roster
    set .@count, getmapunits(BL_NPC, "prontera", .@npc_names$[0]);

    mes "^0000FF[In-Town Inspector]^000000";
    mes "Found ^00FF00" + .@count + "^000000 active script units in Prontera town boundaries.";
    next;

    freeloop(1);
    for (set .@i, 0; .@i < getarraysize(.@npc_names$); set .@i, .@i + 1) {
        mes "Active NPC " + (.@i + 1) + ": [^0055FF" + .@npc_names$[.@i] + "^000000]";
    }
    freeloop(0);
    close;
}

      Example 3: Using getareaunits to Track Monsters 💡

      Target Mob Hunter:
      //===== rAthena Script =======================================
//= Target Mob Area Sweeper
//============================================================
prontera,155,185,4	script	Coliseum Janitor	909,{
    mes "^0000FF[Coliseum Janitor]^000000";
    mes "Hmm, let me check the coliseum arena pit coordinates.";
    next;

    // Query active monsters inside a designated coordinate box (154,186 to 159,182) on 'prontera'
    // Fills an integer array with unique GIDs of matching monsters
    set .@mobs_found, getareaunits(BL_MOB, "prontera", 154, 186, 159, 182, .@gids[0]);

    mes "^0000FF[Coliseum Janitor]^000000";
    mes "Total monsters found in coordinate box: ^FF0000" + .@mobs_found + "^000000.";
    next;

    if (.@mobs_found <= 0) {
        mes "The coordinate sector is thoroughly swept. Clear and safe!";
        close;
    }

    mes "Spawns registered GID list:";
    freeloop(1);
    for (set .@i, 0; .@i < getarraysize(.@gids); set .@i, .@i + 1) {
        mes "Active Monster Gid: ^0055FF" + .@gids[.@i] + "^000000";
    }
    freeloop(0);
    close;
}

      Understanding these Examples:

      Each of the showcase scripts demonstrates a different level of targeting scope using the get*units suite of commands:

      🔍 Example 1: Global Player Auditing (getunits)

      The Imperial Scanner uses getunits(BL_PC, .@names$[0]) to perform a global search of all connected player characters (BL_PC).

      • It stores the total player count in the variable .@num.
      • The string names of all online characters are dynamically written into the temporary string array .@names$.
      • Because server populations can grow quite large, we safely bracket the print loop inside freeloop(1) to bypass the script execution limit and avoid CPU lock-ups.

      🏢 Example 2: Local Map Auditing (getmapunits)

      The In-Town Inspector is configured to sweep a specific map rather than the entire server, calling getmapunits(BL_NPC, "prontera", .@npc_names$[0]).

      • The query filters for NPC objects specifically (BL_NPC) only inside the boundaries of "prontera".
      • It automatically fills .@npc_names$ with the unique script names of every active NPC loaded there.

      🎯 Example 3: Precise Area Coordinate Auditing (getareaunits)

      The Coliseum Janitor performs pixel-perfect coordinate detection, sweeping a precise bounding rectangular area with getareaunits(BL_MOB, "prontera", 154, 186, 159, 182, .@gids[0]).

      • Rather than counting all monsters on the entire map, it restricts search targets to the rectangle formed by corner coordinates (154, 186) and (159, 182).
      • It searches specifically for alive spawned monsters (BL_MOB).
      • Because we supplied an integer array (.@gids[0]), the engine populates it with the active numeric Game IDs (GIDs) of the monsters rather than string names. This allows other commands to target those specific monsters subsequently.
