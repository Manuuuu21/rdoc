      instance_live_info()

      What is instance_live_info? 🤔

      Returns the specified <info type> of instance attached to the npc or, if an instance ID is specified, of that instance.

      Syntax of instance_live_info 📜

      • instance_live_info(<info type>{,<instance id>});

      Syntax Parameter Explanation 🧩

      Parameter Type Description
      <info type> Integer The type of information to retrieve (see valid types below).
      <instance id> (Optional) Integer The unique instance ID. If omitted, defaults to the instance attached to the current script/player.

      Constants & Options ⚙️

      Valid <info type>:

      Constant / Value Description
      ILI_NAME Instance Name Return the name of the instance or "" if that fails.
      ILI_MODE Instance Mode Return IM_NONE, IM_CHAR, IM_PARTY, IM_GUILD, IM_CLAN or -1 if that fails.
      ILI_OWNER Owner ID Return an ID according to the instance mode of the instance attached/specified or -1 if that fails. When the instance mode is IM_NONE, ILI_OWNER will return the npc ID that created the instance,
      IM_CHAR the owner char ID
      IM_PARTY the party ID
      IM_GUILD the guild ID
      IM_CLAN the clan ID

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= instance_live_info Demonstration NPC
//= Demonstrates how to use instance_live_info
//============================================================
prontera,150,150,4	script	InstanceLiveInfoDemo	100,{
    mes "[InstanceLiveInfoDemo]";
    // Return the instance name of the instance attached to the npc.
        .@instance_name$ = instance_live_info(ILI_NAME);

        // Return the guild owner ID of the given instance ID.
        .@owner = instance_live_info(ILI_OWNER, instance_id(IM_GUILD));
    close;
}

      In this script:

      • The script defines an NPC object on prontera (or the target map) that triggers when a player interacts with it.
      • It invokes instance_live_info with the required arguments as specified in the rAthena scripting reference.
      • Any resulting state change, return value, or player/unit update is processed immediately within the active script execution context.
