      cartcountitem, storagecountitem, guildstoragecountitem, cartcountitem2, storagecountitem2, guildstoragecountitem2

      What are cartcountitem, storagecountitem, guildstoragecountitem, cartcountitem2, storagecountitem2, guildstoragecountitem2? 🤔

      This command behaves identically to countitem, but counts items from the player's cart, storage, or guild storage.

      If no cart is mounted, cartcountitem will return -1. If player is not in a guild or storage is open, guildstoragecountitem will return -1.

      This command behaves identically to countitem2, but counts items from the player's cart, storage, or guild storage.

      If no cart is mounted, cartcountitem2 will return -1. If player is not in a guild or storage is open, guildstoragecountitem2 will return -1.

      Syntax of cartcountitem, storagecountitem, guildstoragecountitem, cartcountitem2, storagecountitem2, guildstoragecountitem2 📜

      • cartcountitem(<item id>{,<accountID>})
      • cartcountitem("<item name>"{,<accountID>})
      • storagecountitem(<item id>{,<accountID>})
      • storagecountitem("<item name>"{,<accountID>})
      • guildstoragecountitem(<nameID>{,<accountID>})
      • guildstoragecountitem("<item name>"{,<accountID>})
      • cartcountitem2(<item id>,<identify>,<refine>,<attribute>,<card1>,<card2>,<card3>,<card4>{,<accountID>})
      • cartcountitem2("<item name>",<identify>,<refine>,<attribute>,<card1>,<card2>,<card3>,<card4>{,<accountID>})
      • storagecountitem2(<item id>,<identify>,<refine>,<attribute>,<card1>,<card2>,<card3>,<card4>{,<accountID>})
      • storagecountitem2("<item name>",<identify>,<refine>,<attribute>,<card1>,<card2>,<card3>,<card4>{,<accountID>})
      • guildstoragecountitem2(<nameID>,<Identified>,<Refine>,<Attribute>,<Card0>,<Card1>,<Card2>,<Card3>{,<accountID>})
      • guildstoragecountitem2("<item name>",<Identified>,<Refine>,<Attribute>,<Card0>,<Card1>,<Card2>,<Card3>{,<accountID>})

      Syntax Parameter Explanation 🧩

      Parameter Type Description
      <item id> Integer The database ID of the item from item_db.yml.
      <accountID> (Optional) Integer The target account ID (AID). If omitted, defaults to the currently attached player.
      "<item name>" String The English or Aegis name of the item from item_db.yml.
      <nameID> Integer The database ID of the item.
      <identify> Integer Identification state: 1 = identified, 0 = unidentified.
      <refine> Integer The refine (upgrade) level of the equipment (e.g., 0 to 20).
      <attribute> Integer Equipment broken state: 0 = normal (not broken), 1 = broken.
      <card1> Integer Item ID of the card or enchant in slot 1 (or 0 if empty).
      <card2> Integer Item ID of the card or enchant in slot 2 (or 0 if empty).
      <card3> Integer Item ID of the card or enchant in slot 3 (or 0 if empty).
      <card4> Integer Item ID of the card or enchant in slot 4 (or 0 if empty).
      <Identified> Integer Identification state: 1 = identified, 0 = unidentified.
      <Card0> Integer Item ID of the card or enchant in slot 1 (or 0 if empty).

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= cartcountitem, storagecountitem, guildstoragecountitem, cartcountitem2, storagecountitem2, guildstoragecountitem2 Demonstration NPC
//= Demonstrates how to use cartcountitem, storagecountitem, guildstoragecountitem, cartcountitem2, storagecountitem2, guildstoragecountitem2
//============================================================
prontera,150,150,4	script	CartcountitemDemo	100,{
    mes "^0000FF[CartcountitemDemo]^000000";
    mes "Testing the cartcountitem command.";
    next;

    .@result = cartcountitem(501);
    mes "Result of cartcountitem: " + .@result;
    close;
}

      In this script:

      • The script defines an NPC object on prontera (or the target map) that triggers when a player interacts with it.
      • It invokes cartcountitem with the required arguments as specified in the rAthena scripting reference.
      • Any resulting state change, return value, or player/unit update is processed immediately within the active script execution context.
