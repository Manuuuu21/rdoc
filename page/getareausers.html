      getareausers()

      What is getareausers? 🤔

      The getareausers() function retrieves the total count of connected characters currently standing inside a bounding box rectangle formed by the coordinates (x1, y1) and (x2, y2) on the specified map name.

      This function is extremely valuable on map designs that package multiple distinct building interiors or separate merchant shops onto a single master file coordinate layout (such as the standard *_in interior files). Standard map-wide queries would return inaccurate false positives from adjacent, isolated shop zones; getareausers() focuses precisely on the requested zone.

      Syntax of getareausers? 📜

      • getareausers("<map name>", <x1>, <y1>, <x2>, <y2>)

      Syntax Parameter Explanation 🧩

      Parameter Type Description
      "<map name>" String The string designating the target map coordinate registry (e.g. "prontera_in").
      <x1>, <y1> Integer The exact starting coordinate corner (bottom-left corner of the target rectangle).
      <x2>, <y2> Integer The exact ending coordinate corner (top-right corner of the target rectangle).

      Return Value ↩️

      • Returns an **integer** detailing the player head-count currently located within the configured boundary zone.
      • Returns **0** if there are no player structures there, or if the specified coordinate bounds or map key are configured incorrectly.

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= Restricted VIP Lounge Cabin Doorman NPC
//===== By: rAthena AI Assistant ============================
//= Showcases getareausers() inside multi-interior spaces
//============================================================
prontera_in,15,40,4	script	VIP Lounge Attendant	909,{
    // We are situated inside 'prontera_in'.
    // The VIP Lounge is a private rectangle partitioned from coordinate 10,35 to 20,45.
    // Let's verify how many elites are inside the cabin.
    set .@active_elites, getareausers("prontera_in", 10, 35, 20, 45);

    mes "^0000FF[Lounge Attendant]^000000";
    mes "Greetings! Let me inspect the cabin's booking threshold.";
    mes "This private cabin is limited to ^00FF005 players^000000 simultaneously.";
    next;

    mes "^0000FF[Lounge Attendant]^000000";
    mes "Active occupants inside the lounge zone: ^0055FF" + .@active_elites + " / 5^000000.";
    next;

    if (.@active_elites >= 5) {
        mes "^0000FF[Lounge Attendant]^000000";
        mes "Oh dear! The lounge room is currently packed with VIP patrons.";
        mes "Please wait a moment until someone vacates the cabin area.";
        close;
    }

    mes "^0000FF[Lounge Attendant]^000000";
    mes "Would you like me to open the velvet rope and let you in?";
    next;

    if (select("Yes, please!:No thanks") == 1) {
        warp "prontera_in", 15, 38; // Teleport player directly inside the target zone
        end;
    }

    mes "^0000FF[Lounge Attendant]^000000";
    mes "Understood. Have a peaceful stay!";
    close;
}

      In this script:

      The Attendant NPC implements surgical density targeting:

      • The command getareausers("prontera_in", 10, 35, 20, 45) isolates the coordinates of VIP chamber specifically on line 7, ignoring players occupying other adjacent spaces on "prontera_in".
      • This keeps our custom system mechanics perfectly bounded, cleanly eliminating overflow check bugs standard with standard map-wide scripts.
