      checkoption, setoption

      What are options? 🤔

      In rAthena, character "Options" represent bit-masked flag collections that store active status conditions, temporary graphic properties, mounts, visual outfits, and non-permanent character statuses of a yes/no structure.

      The checkoption family checks these flags on a player, while setoption toggles them on or off. Note that while there are three distinct checker methods mapping separate client-side registers, only the first register can be actively written to using setoption.

      Syntax Specifications 📜

      • checkoption(<option number>{, <char_id>})
      • checkoption1(<option number>{, <char_id>})
      • checkoption2(<option number>{, <char_id>})
      • setoption <option number>{, <flag>{, <char_id>}};

      Option register values 🧩

      2. Status Options 1 (checkoption1 Register)

      Note: These states do not operate as standard bitmasks; checkoption1 will return the exact state ID currently active.

      Value (Constant ID) State Mapping
      1Petrified (fully rigid stone state)
      2Frozen (encased in ice)
      3Stunned (stars circling head)
      4Sleeping status active
      6Petrifying (transitional phase - character can still walk)

      3. Status Options 2 (checkoption2 Register)

      Value (Bitmask) State Mapping
      0x1Standard Poisoned status active
      0x2Cursed status active
      0x4Silenced status active
      0x8Signum Crucis active (plays continuous sound effect)
      0x10Blinded status active
      0x80Deadly poisoned (Guillotine Cross venom)

      Return Values ↩️

      • Returns **1** if at least one of the queried bitmask flag conditions is currently set and active.
      • Returns **0** if none of the target option conditions are in effect.

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= Wedding Chapel Coordination NPC
//= Showcases setoption to apply wedding sprite and checks frozen
//============================================================
prontera,165,190,4	script	Bridal Coordinator	105,{
    mes "^0000FF[Bridal Coordinator]^000000";
    mes "Ah! Welcome to the chapel grounds.";
    mes "Before proceeding, please dress for the occasion.";
    next;

    select("Equip Formal Gown/Tuxedo", "Remove Gown/Tuxedo", "Check if Stunned or Frozen");
    next;

    if (@menu == 1) {
        // Toggle the visual option for wedding sprite on (0x1000)
        setoption 0x1000, 1;
        mes "Tada! You look stunningly formal.";
        close;
    } else if (@menu == 2) {
        // Toggle the wedding sprite off (0x1000)
        setoption 0x1000, 0;
        mes "Wedding sprite successfully cleared.";
        close;
    } else {
        // Check for specific disabling options.
        // checkoption1(2) matches standard Frozen, checkoption1(3) matches Stunned
        if (checkoption1(2) || checkoption1(3)) {
            mes "Error! You are currently incapacitated and cannot walk down the aisle.";
            close;
        }

        mes "All conditions are clear! You are fully alert and ready.";
        close;
    }
}

      In this script:

      The Bridal Coordinator executes precise visual toggles and status lookups:

      • On line 15, we call setoption 0x1000, 1 to write a main option mask flag, enabling the client to immediately draw the player character wearing their wedding sprites.
      • On line 20, passing setoption 0x1000, 0 clears the bit, returning the rendering queue to standard gear models.
      • In the third branch starting on line 24, we use checkoption1(2) and checkoption1(3) to make sure they are not stunned or frozen, preventing game-state exploits inside specific wedding ceremony triggers.
