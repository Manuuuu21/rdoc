      classchange()

      What is classchange()? ⚠️ 🤔

      The classchange() command is a very ancient script instruction designed to temporarily send a "display ID change" packet to surrounding players, which forces an NPC's character model/sprite to visually transform.

      Important Note: Under modern rAthena codebases, this command was rendered semi-broken due to conflicts introduced with advanced rebirth and baby classes. Its use is generally discouraged in favor of standard NPC view properties, but it remains supported for legacy backward compatibility.

      The modification is transient state; it does not persist in SQL tables and is reset immediately once players clear their cache or the map restarts.

      Syntax of classchange() 📜

      • classchange(<view id>{, "<NPC name>", "<flag>"});

      Parameters 🎯

      • <view id>: The visual sprite ID (monster ID or NPC sprite ID) to display.
      • "<NPC name>" (Optional): The name of the NPC to alter. Leaving this blank (or omitting it) defaults to the currently attached NPC context.
      • "<flag>" (Optional): Controls where the rendering packet is sent:
        • - "bc_area": Packet is sent to of all players within the visual vicinity of the source. [Default]
        • - "bc_self": Packet is sent exclusively to the invoking attached player.

      Example Usage 💡

      Example Code:
      prontera,150,150,4	script	Shapeshifter NPC	99,{
    mes "^0000FF[Shapeshifter]^000000";
    mes "Witness my mysterious transformation!";
    next;
    
    // Change current NPC view ID to 1002 (Poring Sprite ID) for all close players
    classchange(1002, "Shapeshifter NPC", "bc_area");
    
    mes "^0000FF[Poring-NPC]^000000";
    mes "Boing! I am now a Poring visually!";
    close;
}

      In this script:

      • On line 6, classchange(1002) changes the sprite texture design to present index 1002 (Poring monster model) dynamically.
