      checkvending()

      What is checkvending? 🤔

      The checkvending() function queries the commercial state of a player on the server. This maps their active storefront status, buying store stalls, and offline trading presence.

      Before warping characters during server-wide operations, custom events, or instanced queues, testing checkvending() is crucial. Moving merchants actively trading can break client-side rendering or create visual glitches, making this function a high-priority safeguard.

      Syntax of checkvending? 📜

      • checkvending({"<Player Name>"})

      Syntax Parameter Explanation 🧩

      Parameter Type Description
      "<Player Name>" (Optional) String / Character Name The name of the player to audit. If omitted, defaults to evaluating the currently attached player character.

      Return Values (Bitmask Mapping) ↩️

      Note: These returned values can be combined additively depending on active state modifiers (e.g., autotraded vending stores returns 3).

      Returned Value (Bitmask) Commercial State Meaning
      0No active store, buying store, or offline trade setup active.
      1Normal Vending open (active player shop).
      2Autotrade active (using @autotrade offline store representation).
      4Active Purchasing/Buying Store stall open.

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= Market District Warp Warden
//= Showcases checkvending() bitmask checks to block teleports
//============================================================
prontera,164,180,4	script	Market Warden	107,{
    mes "^0000FF[Market Warden]^000000";
    mes "Greetings! I operate port transportation to Payon Meadows.";
    mes "Before proceeding, server guidelines require store compliance.";
    next;

    // Check vending status
    set .@state, checkvending();

    if (.@state & 1) {
        mes "^0000FF[Market Warden]^000000";
        mes "Error: active shop detected! Please close your vending shop before warp.";
        close;
    }
    
    if (.@state & 4) {
        mes "^0000FF[Market Warden]^000000";
        mes "Error: buying store detected! Please close your purchase stall first.";
        close;
    }

    if (.@state & 2) {
        mes "^0000FF[Market Warden]^000000";
        // Highly uncommon for attached active sessions, but is checked here
        mes "Status error: offline autotrading flag detected.";
        close;
    }

    mes "^0000FF[Market Warden]^000000";
    mes "Perfect! No conflicting store presence found.";
    mes "Ready to warp?";
    next;
    
    if (select("Yes, please!:No, wait") == 1) {
        warp "pay_fild04", 100, 100;
    }
    close;
}

      In this script:

      The Market Warden ensures store states are cleared:

      • The warden reads active conditions using checkvending() on line 12.
      • We perform bitwise evaluation: .@state & 1 on line 14 checks if a vending stall is open.
      • Bitwise evaluation .@state & 4 on line 19 detects client-side item purchasing setups.
      • If the user possesses any non-zero state, transition portals remain locked, avoiding marketplace abuse.
