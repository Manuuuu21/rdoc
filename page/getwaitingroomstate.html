      getwaitingroomstate()

      What is getwaitingroomstate? 🤔

      This function will return information about the waiting room state for the attached waiting room or for a waiting room attached to the specified NPC if any.

      Syntax of getwaitingroomstate 📜

      • getwaitingroomstate(<information type>{,"<NPC object name>"})

      Syntax Parameter Explanation 🧩

      Parameter Type Description
      <information type> Integer The type of information to retrieve (see valid types below).
      "<NPC object name>" (Optional) String The unique object name of the target NPC.

      Constants & Options ⚙️

      The valid information types are:

      Constant / Value Description
      0 Number of users currently chatting.
      1 Maximum number of users allowed.
      2 Will return 1 if the waiting room has a trigger set. 0 otherwise.
      3 Will return 1 if the waiting room is currently disabled. 0 otherwise.
      4 The Title of the waiting room (string)
      5 Password of the waiting room, if any. Pointless, since there is no way to set a password on a waiting room right now.
      16 Event name of the waiting room (string)
      32 Whether or not the waiting room is full.
      33 Whether the amount of users in the waiting room is higher than the trigger number.

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= getwaitingroomstate Demonstration NPC
//= Demonstrates how to use getwaitingroomstate
//============================================================
prontera,150,150,4	script	GetwaitingroomstateDemo	100,{
    mes "^0000FF[GetwaitingroomstateDemo]^000000";
    mes "Testing the getwaitingroomstate command.";
    next;

    .@result = getwaitingroomstate(0);
    mes "Result of getwaitingroomstate: " + .@result;
    close;
}

      In this script:

      • The script defines an NPC object on prontera (or the target map) that triggers when a player interacts with it.
      • It invokes getwaitingroomstate with the required arguments as specified in the rAthena scripting reference.
      • Any resulting state change, return value, or player/unit update is processed immediately within the active script execution context.
