      playerattached()

      What is playerattached? 🤔

      The playerattached() function is used to check which player character is currently attached to the running script thread. It also determines if they are still connected to the active map-server.

      This function is critical for delayed script threads such as timers, sleep sequences, or asynchronous callbacks, where there is a risk that the player disconnected or logged off while the script was waiting to finalize its operations. Attempting to perform character operations on a detached or offline player will cause map-server warning logs ("player not attached!").

      Syntax of playerattached? 📜

      • playerattached()

      Return Values ↩️

      • Returns the **Account ID** (also called **RID**) of the connected player currently attached to the script.
      • Returns **0** if no player is attached to the script thread, or if the previously attached player is no longer logged on.

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= Delayed Reward Timer NPC
//= Showcases playerattached() to prevent offline errors
//============================================================
prontera,150,180,4	script	Reward Timer Guard	100,{
    mes "^0000FF[Timer Guard]^000000";
    mes "Ah, welcome! I can register you for a delayed supply drop.";
    mes "Stand near me for 10 seconds to receive your rewards.";
    next;
    
    // Start a 10,000ms delay timer bound to a labels trigger
    addtimer 10000, "Reward Timer Guard::OnRewardReward";
    mes "Timer started! Stay online.";
    close;

OnRewardReward:
    // This label triggers after 10s. We MUST check if player is still attached.
    if (playerattached() == 0) {
        // Player disconnected during the 10 seconds. Terminate gracefully.
        end;
    }
    
    // Player is still online! Give rewards safely.
    getitem 512, 5; // Give 5 Apples
    dispbottom "The 10 seconds have elapsed! Your food drop has safely arrived.";
    end;
}

      In this script:

      The Delayed Reward Guard relies on player-attached states to avoid failures:

      • We trigger addtimer on line 11 to fire a callback event after 10 seconds.
      • Inside the OnRewardReward: label on line 17, we perform a safety check using playerattached() == 0.
      • If the player logged out during that timer, playerattached() returns 0, allowing the script engine to exit immediately with end; without throwing severe "player not attached!" errors on the console.
