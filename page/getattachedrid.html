      getattachedrid()

      What is getattachedrid? 🤔

      The getattachedrid() function retrieves the Registration ID (RID) associated with the currently running script engine execution stream.

      When run inside standard player-triggered scripts, this returns the Account ID of the player currently invoking or attached to the script. When triggered inside monster event/idle scripts (configured via mob_setidleevent or OnTouchNPC), it returns the monster's unique Game ID (GID). If the current thread is not attached to any target, such as inside a floating function or script that initialized via OnInit:, it returns 0.

      Syntax of getattachedrid? 📜

      • getattachedrid()

      Return Values ↩️

      • Returns the **RID** (numerical character account ID, or monster GID) linked to the active thread.
      • Returns **0** if there is no attached entity mapping.

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= Intelligent Idle Talking Monster & Quest Marker
//= Showcases getattachedrid() in a monster-authoritative context
//============================================================
prontera,164,180,4	script	Beast Master NPC	703,{
    mes "^0000FF[Beast Master]^000000";
    mes "Stay vigilant! I coordinate active summons to patrol the perimeter.";
    next;

    // Spawn a patrol target
    monster "prontera", 150, 185, "Quest Poring", 1002, 1, "Beast Master NPC::OnMobSpawned";
    mes "Patrol spawned! Run along now.";
    close;

OnMobSpawned:
    // Get GID of the spawned monster and assign its idle patrol event
    set .@mobid, getattachedrid();
    mob_setidleevent .@mobid, "Beast Master NPC::OnMobIdle";
    end;

OnMobIdle:
    // This is run by the patrol monster when it enters idle state.
    // getattachedrid() returns the monster's Game ID (GID) here!
    set .@monster_git, getattachedrid();
    mobchat .@monster_git, 0, 0x00FF00, "Beast Master:: Patrolling area safely!";
    end;
}

      In this script:

      The Beast Master coordinates real-time entity tracking:

      • When a monster is successfully created using monster with an event callback on line 10, the engine launches a thread where getattachedrid() evaluates to the newly created monster's internal GID on line 16.
      • Inside the idle patrol event OnMobIdle: on line 20, getattachedrid() is checked to identify which exact spawned monster unit went idle.
      • This enables mobchat to broadcast text bubbles originating precisely from that specific monster's position.
