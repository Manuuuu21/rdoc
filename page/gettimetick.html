      gettimetick()

      What is gettimetick? 🤔

      The gettimetick() command returns various high-fidelity tick counts representing system time structures, depending on the specified metric requested.

      This function is the quintessential backbone of rAthena delay checks, quest cooldowns, item lockouts, speed runs, and instance time trackers. Using Unix Epoch offsets, developers can easily calculate specific cooldown differences (e.g. locking an event reward for exactly 24 hours).

      Syntax of gettimetick? 📜

      • gettimetick(<tick type>)

      Syntax Parameter Explanation 🧩

      Tick Type Argument Representation Class Description & Common Handlers
      0 Server-specific Milliseconds The internal server execution clock tick cycle, measured in **milliseconds**. Loop cycles wrap / reset every ~50 system days. Excellent for high-speed microtimers.
      1 Seconds Since Midnight Returns the exact number of seconds elapsed since the start of the current day. Clears/resets back to zero every midnight. Good for daily resetting schedule.
      2 UNIX Epoch Seconds Returns the standard system timestamp indicating the total number of seconds elapsed since **January 1st, 1970 (UTC)**. Highly recommended for absolute date timers.

      Return Value ↩️

      • Returns an **integer** value representing the specific count of seconds or milliseconds relative to the requested configuration type.

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= Quest/Reward Cooldown Management System
//===== By: rAthena AI Assistant ============================
//= Showcases gettimetick(2) to enforce a clean 24-Hour limit
//============================================================
prontera,150,160,4	script	Daily Gift Giver	909,{
    mes "^0000FF[Daily Assistant]^000000";
    mes "Hello there, adventurer! I give free daily gifts to persistent travelers.";
    next;

    // Secure the current Unix epoch time
    set .@now, gettimetick(2);

    // Cooldown verification (24 Hours block = 86400 seconds)
    // Cooldown variables should be stored per character (permanent integer variable)
    if (.@now < MyDailyReward_Cooldown) {
        set .@seconds_left, MyDailyReward_Cooldown - .@now;
        set .@hours_left, .@seconds_left / 3600;
        set .@minutes_remaining, (set .@seconds_left - (set .@hours_left * 3600)) / 60;

        mes "^0000FF[Daily Assistant]^000000";
        mes "Wait a second! You already claimed your daily gift package.";
        mes "Please visit me again in ^FF0000" + .@hours_left + " hours and " + .@minutes_remaining + " minutes^000000.";
        close;
    }

    mes "^0000FF[Daily Assistant]^000000";
    mes "You are eligible! Let me generate your daily package.";
    next;

    // Set new cooldown milestone (24 hours offset)
    set MyDailyReward_Cooldown, .@now + 86400;

    // Grant bounty
    getitem 501, 10; // Red Potion x 10
    mes "^0000FF[Daily Assistant]^000000";
    mes "Clang! You have received 10 Red Potions!";
    mes "Your next reward will unlock in exactly 24 hours.";
    close;
}

      In this script:

      The Daily Gift Giver NPC highlights accurate calendar-independent timers:

      • The system retrieves the active UTC epoch timestamp on line 10 via gettimetick(2).
      • It references the player's saved character integer variable MyDailyReward_Cooldown.
      • If the current system time is smaller, the player is rejected, and the script dynamically divides the remaining seconds to report a highly human-friendly readout of remaining hours/minutes.
      • If eligible, the milestone is refreshed forward by exactly 24 hours (MyDailyReward_Cooldown = .@now + 86400).
