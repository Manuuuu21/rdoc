      npcspeed, npcwalkto, npcstop

      What are npcspeed, npcwalkto, npcstop? 🤔

      These commands will make the NPC object in question move around the map.

      npcspeed will permanently set the NPCs walking speed to a specified value. As in the @speed GM command, MAX_WALK_SPEED (1000) is the slowest possible speed while MIN_WALK_SPEED (20) is the fastest possible (instant motion). DEFAULT_NPC_WALK_SPEED (200) is the default NPC walking speed.

      npcwalkto will start the NPC sprite moving towards the specified coordinates on the same map it is currently on. The script proceeds immediately after the NPC begins moving.

      npcstop will stop the motion.

      While in transit, the NPC will be clickable, but invoking it will cause it to stop moving, which will make its coordinates different from what the client computed based on the speed and motion coordinates.

      Only a few NPC sprites have walking animations, and those that do, do not get the animation invoked when moving the NPC, due to the problem in the NPC walking code, which looks a bit silly. You might have better success by defining a job- sprite based sprite id in db/mob_avail.yml with this.

      Syntax of npcspeed, npcwalkto, npcstop 📜

      • npcspeed( <speed value> {,"<npc name>"} );
      • npcwalkto( <x>,<y> {,"<npc name>"} } );
      • npcstop( {"<npc name>", {"<flag>"}});

      Syntax Parameter Explanation 🧩

      Parameter Type Description
      <speed value> Integer Specifies the <speed value> parameter for npcspeed.
      "<npc name>" (Optional) String The unique name of the target NPC object. If omitted, defaults to the current NPC.
      <x> Integer The X coordinate on the map.
      <y> Integer The Y coordinate on the map.
      "<, {>" String Specifies the <, {> parameter for npcspeed.
      "<flag>" (Optional) Integer Bitmask or mode flag controlling specific behavior of the command (see flag options below).

      Constants & Options ⚙️

      Constant / Value Description
      USW_NONE Unit will keep walking to their original destination.
      USW_FIXPOS Issue a fixpos packet afterwards.
      USW_MOVE_ONCE Force the unit to move one cell if it hasn't yet.
      USW_MOVE_FULL_CELL Enable moving to the next cell when unit was already half-way there (may cause on-touch/place side-effects, such as a scripted map change).
      USW_FORCE_STOP Force stop moving.
      Default USW_FIXPOS | USW_MOVE_FULL_CELL | USW_FORCE_STOP

      Example Usage 💡

      Example Code:
      //===== rAthena Script =======================================
//= npcspeed, npcwalkto, npcstop Demonstration NPC
//= Demonstrates how to use npcspeed, npcwalkto, npcstop
//============================================================
prontera,150,150,4	script	NpcspeedDemo	100,{
    mes "^0000FF[NpcspeedDemo]^000000";
    mes "Testing the npcspeed command.";
    next;

    .@result = npcspeed(50);
    mes "Result of npcspeed: " + .@result;
    close;
}

      In this script:

      • The script defines an NPC object on prontera (or the target map) that triggers when a player interacts with it.
      • It invokes npcspeed with the required arguments as specified in the rAthena scripting reference.
      • Any resulting state change, return value, or player/unit update is processed immediately within the active script execution context.
